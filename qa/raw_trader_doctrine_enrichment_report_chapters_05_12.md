# P11.2A Raw Trader-Doctrine Enrichment Report: Chapters 5-12

Mission ID: TMR-P11.2A-RAW-TRADER-DOCTRINE-ENRICHMENT-CH05-CH12
Review date: 2026-05-21
Reviewer pass: First pass of a two-pass chain — raw trader-action enrichment (Pass A). A later Pass B must normalize the added language into the project's final non-executional standard.

## Executive Result

- **Overall result: ENRICHMENT_APPLIED.**
- **Chapters edited:** 8 (Chapters 5, 6, 7, 8, 9, 10, 11, 12).
- **Concepts edited:** 38.
- **Concepts reviewed but left unchanged:** 30.
- **Concepts judged too passive or under-informative (and enriched):** All 38 edited concepts. Each one was technically accurate and already "actionable in judgment," but stopped short of the raw trader-action doctrine — explicit fade / press / join / lean-with / take-the-other-side / stand-aside / do-not-chase language — that an experienced discretionary futures trader would naturally include when teaching the concept. The dominant weakness was that Practical Implications named conditions ("treat as a warning," "be cautious," "watch whether") without naming the resulting trader posture.
- **Why enrichment was added before non-executional normalization:** This pass deliberately asked a different question than a compliance audit: *are Chapters 5-12 less educational because practical trader-action doctrine was suppressed?* The answer is yes for 38 concepts. Chapters 2-4 — used here only as a style reference — carry rich, raw trader-action doctrine (explicit "fade the rejection," "join it on the first pullback," "fade the edges of balance, join the direction of imbalance"). Chapters 5-12 were written in a more restrained voice and, by comparison, teach the *what* and the *why* but frequently withhold the *what the trader does now*. Recovering that raw doctrine first — before normalization — makes the lost trader education visible and explicit so Pass B can reclassify it deliberately rather than leaving it unwritten.

## Method

- This pass intentionally searched for missing trader-action doctrine. It did **not** apply the project's final non-executional cleanup, and it did not treat `PROJECT_PROTOCOL.md`, Chapter 1, the QA checklist, or Chapter 12 governance text as constraints for the review.
- Every concept in Chapters 5-12 was read in full and classified internally against the rubric: ROBUST_AS_WRITTEN, NEEDS_TRADER_ACTION_DOCTRINE, TOO_ACADEMIC_OR_PASSIVE, NEEDS_PLAYBOOK_LANGUAGE, or DO_NOT_CHANGE.
- Chapters 2-4 were read as style/completeness references only and were not edited. They confirmed the comparison point: the project's earlier chapters carry far more raw trader-action language than Chapters 5-12.
- Edits were targeted: 1-3 bullets appended to **Practical Implications**, using raw educational trader language (fade, press, join, lean with/against, stand aside, wait, do not chase, take the other side, reversal/continuation trigger, stop-run candidate, use as magnet/target, define invalidation around the failed reference, reduce/scale back conviction, hold/abandon the read). No `## ` concept headings were added, no concept inventory was altered, no headings were normalized, no detection specs or thresholds were created.
- Raw educational language was added where it materially improves the concept. It was **not** added where the concept is already trader-useful, where the concept's core discipline is "this is context, not evidence" (raw fade/press language would damage it), or where the concept is itself a stand-aside/refusal concept that already teaches the posture.
- Hard safety boundaries were respected even in this raw pass: no current-market calls, no instrument-specific live calls, no exact price/stop/target levels, no sizing formulas, no broker/order-routing instructions, no account-management rules, no guaranteed outcomes, and no universal always/never claims on regime-dependent conditions. All added doctrine is conditioned ("in a confirmed trend day," "once the tape confirms refusal," "candidate," "condition").
- This is a raw pass. **A later Pass B must normalize every added phrase into the project's final non-executional standard.** See "Language Added That Needs Later Normalization."

## Language Added That Needs Later Normalization

Every phrase added in this pass is raw trader-action language and **must be reviewed and reclassified in Pass B** into the project's final non-executional standard ("actionable in judgment, non-executional in instruction"). The raw verbs and phrases introduced are:

- **Direct action verbs:** fade, press / do not press, join, lean with, lean against, take the other side, chase / do not chase, stand aside, abandon the read, hold the read.
- **Trigger and target phrasing:** reversal trigger, continuation trigger, join condition, fade candidate, take-the-other-side condition, stop-run candidate, fade-the-headline-reaction, treat the failed extreme as a magnet.
- **Conviction phrasing:** reduce conviction, scale back conviction, tighten the read, conviction upgrade.
- **Risk phrasing:** "define invalidation around the failed reference / around acceptance through the level" — conceptual invalidation only; no exact prices were written, but Pass B should confirm this maps cleanly to the approved invalidation-condition language.

Pass B normalization guidance: each added bullet should be reclassified into the protocol's semantic categories — read-quality implication, setup-quality implication, location-quality implication, confirmation requirement, invalidation condition, thesis-state change, posture label, watch-next instruction, evidence downgrade, or no-clean-expression condition — using the reclassification examples already in `PROJECT_PROTOCOL.md` Section 3.1 (e.g., "fade the rejection" → "a clean rejection strengthens a rejection thesis if price fails to accept beyond the reference"). All 38 edited concepts contain language requiring this treatment. No exact entries, stops, targets, sizing, or broker/order instructions were introduced, so Pass B is a language-reclassification pass, not a safety remediation.
