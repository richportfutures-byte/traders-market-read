# TMR-P25 — Safe Detector Runtime v1 — Implementation Report

Mission: TMR-P25 Safe Detector Runtime v1
Status: Complete. The runtime works end-to-end against all 110 detector contracts.
Date: 2026-05-21

---

## 1. What now works

The first working safe detector runtime exists. It:

1. Loads the 110 detector contracts from `spec/detector_contract_catalog.json`
   (fail-closed: a missing file, malformed record, duplicate id, missing
   required field, or unknown determinism class raises `CatalogError`).
2. Runs every contract in one pass and emits exactly one output per contract.
3. Implements real structural behaviour for all 9 `COMPUTABLE` detectors.
4. Emits safe, contract-valid refusal/context/blocked outputs for the 101
   non-computable contracts, routed by determinism class.
5. Self-validates every output and is cross-checked by
   `scripts/validate_detector_output.py`.
6. Is proven by two fixtures (complete inputs and missing inputs) and a
   12-test `unittest` suite.

This is working behaviour, not scaffolding. Every emitted payload is a real,
validated, non-executional detector output.

The runtime is not a trading engine. It creates no trade permission, entries,
stops, targets, sizing, order/broker/account/fill/P&L behaviour, calibration
values, or autonomous trading instructions.

## 3. The `validate_detector_output.py` patch (user-approved)

Two structural facts in the catalog collided with the validator as originally
written. The user explicitly approved a minimal, additive, backward-compatible
patch to reconcile them.

**Fact 1 — output cardinality.** The runtime emits one output per contract
(110 outputs). The validator's `validate_output` rejected any top-level JSON
array. The patched `main()` now accepts either a single output object or a
JSON array of output objects and validates each element.

**Fact 2 — state-only contracts.** Five detectors declare an empty
`allowed_action_labels`. The schema requires an `action_label`, and the
validator required `action_label ∈ allowed_action_labels` — unsatisfiable when
that list is empty. The patched action-label check treats a contract with an
empty `allowed_action_labels` as *state-only*: its `action_label` must be one
of `states_emitted`. The runtime sets `action_label = state` for these.

The five state-only contracts:
`ch02_acceptance_vs_rejection`, `ch02_structural_reference_levels`,
`ch03_initial_balance`, `ch03_value_area_vah_val_poc`, `ch03_vwap_relationship`.

The patch is backward compatible: `qa/examples/detector_output_valid.example.json`
still passes and `qa/examples/detector_output_invalid_execution.example.json`
is still rejected.

This state-only treatment is a label-mapping decision worth GPT-5.5 review:
the detection specs for those five concepts declare no action vocabulary while
the output schema mandates an `action_label`. Either the specs should declare
action labels, or the output schema should formally recognize state-only
detectors. The runtime's mirror-the-state choice is a safe interim mapping.

## 4. COMPUTABLE detectors (9) — real structural behaviour

All 9 `COMPUTABLE` contracts in the catalog are implemented. Each uses explicit
fixture fields only, invents no thresholds, and infers no motive, trend,
reversal, setup quality, or trade opportunity. With the complete-input fixture
each produces a real (non-refusal) structural state:

| concept_id | structural computation | state (complete fixture) |
|---|---|---|
| `ch02_structural_reference_levels` | prior-day high/low from prior-session bars; RTH open from first current-session bar | `OBSERVED` |
| `ch03_initial_balance` | IB high/low/width (max/min over the IB window) | `OBSERVED` |
| `ch03_single_prints` | TPO levels touched by exactly one period bracket | `SINGLE_PRINTS_PRESENT` |
| `ch03_value_area_vah_val_poc` | POC = max-weight level; VAH/VAL by 0.70 coverage expansion | `OBSERVED` |
| `ch03_value_migration_and_overlap` | direct current-vs-prior value-area comparison | `VALUE_MIGRATING_HIGHER` |
| `ch03_vwap_relationship` | session VWAP = Σ(price·volume)/Σ(volume); price-vs-VWAP location | `OBSERVED` |
| `ch05_one_timeframing` | period-by-period high/low control comparison | `ONE_TIMEFRAMING_HIGHER` |
| `ch07_rth_open_location` | open vs overnight, prior-RTH, and prior-value references | `OPEN_INSIDE_OVERNIGHT_RANGE` |
| `ch08_inside_outside_and_narrow_wide_range_days` | current vs prior session range container | `INSIDE_DAY` |

With the missing-input fixture every one of the 9 emits `REFUSE_TO_CLASSIFY`
(route `computable_refusal`) — they refuse rather than guess.

**Threshold-free scope note.** Every implemented computation is threshold-free.
`ch08`'s narrow/wide labels and `ch07`'s near-reference labels require
calibration and are intentionally not emitted (the spec marks them calibrated).
`ch03_value_migration_and_overlap` and `ch03_single_prints` are catalog-class
`COMPUTABLE` but carry `calibration_required` parameters
(`overlap_policy`, `single_print_adjacency_policy`, `fill_detection_policy`):
the runtime implements only their threshold-free structural core (migration
direction / overlap by interval intersection; single-print presence by a
one-bracket count) and does not classify the calibration-dependent
refinements. The `value_area_coverage_fraction` of 0.70 used by
`ch03_value_area_vah_val_poc` is the documented Market Profile method
convention recorded in that detection spec, not an invented market threshold;
it is recorded in the output evidence.

## 5. Non-computable routing (101 contracts)

Determinism-class breakdown of the catalog: `COMPUTABLE` 9, `CALIBRATED` 27,
`JUDGMENT_ASSISTED` 64, `CONTEXT_ONLY` 7,
`NOT_DETECTABLE_WITH_CURRENT_FEEDS` 3 — total 110.

Each non-computable contract is routed to a safe class handler that draws its
state and action label from that contract's own declared vocabulary:

- **`CALIBRATED` (27)** — refusal: the rule structure exists but its thresholds
  are uncalibrated and no calibration profile is available.
- **`JUDGMENT_ASSISTED` (64)** — review-required routing: the concept needs
  structured human/LLM interpretation; no autonomous classification is emitted.
- **`CONTEXT_ONLY` (7)** — context/governance output only; no actionable trigger.
- **`NOT_DETECTABLE_WITH_CURRENT_FEEDS` (3)** — blocked-by-feeds output.

### Label selection and mapping decisions

Label selection walks an ordered matcher list per class and picks the first
label the contract actually declares. Observed label distribution
(complete-input run):

- `CALIBRATED` → `INSUFFICIENT_EVIDENCE` ×23, `REFUSE_TO_CLASSIFY` ×1,
  `DEGRADED_CONFIDENCE` ×2, `ENVIRONMENT_REVIEW_REQUIRED` ×1.
- `JUDGMENT_ASSISTED` → `REVIEW_REQUIRED` ×59, `INSUFFICIENT_EVIDENCE` ×3,
  `PROVISIONAL_INVENTORY_READ` ×1, `POWER_HOUR_REVIEW_REQUIRED` ×1.
- `CONTEXT_ONLY` → `CONTEXT_ONLY` ×4, `CONTEXT_ONLY_OBSERVATION` ×1,
  `PRODUCT_SPECIFIC_CONTEXT_ONLY` ×1, `CONTEXT_ONLY_LABEL` ×1.
- `NOT_DETECTABLE_WITH_CURRENT_FEEDS` → `BLOCKED_BY_FEEDS` ×2,
  `DEALER_GAMMA_FEEDS_UNAVAILABLE` ×1.

Mapping decisions of note:

- For `CALIBRATED`, the protocol's canonical missing-calibration label is
  `INSUFFICIENT_EVIDENCE`; 23 of 27 contracts declare it. The remaining four
  declare no `INSUFFICIENT_EVIDENCE`/`REFUSE_TO_CLASSIFY` state, so the safest
  available label is used: `ch03_volume_nodes_and_air_pockets` →
  `REFUSE_TO_CLASSIFY`; `ch08_expanded_volatility_no_trade_condition` →
  `ENVIRONMENT_REVIEW_REQUIRED`; `ch06_stop_out_cascades_and_liquidation` and
  `ch08_volatility_crush_and_reset` → `DEGRADED_CONFIDENCE`. These last two
  declare *no* canonical refusal state at all and are flagged for review in §8.
- The `"CONTEXT"` substring is deliberately excluded from `CALIBRATED`,
  `JUDGMENT_ASSISTED`, and `NOT_DETECTABLE` label matching, because several
  contracts name substantive market-read states with a `_CONTEXT` suffix
  (e.g. `LIQUIDATION_CONTEXT`, `REALIZED_VOLATILITY_CRUSH_CONTEXT`). A refusal
  must never land on a substantive read. It *is* used for `CONTEXT_ONLY`
  contracts, where a context state is the contractually correct output.
- Every refusal output records its route, reason, and (where a non-obvious
  substitution occurred) a `label_mapping_note` in `evidence`.

No contract required the last-resort first-declared-label fallback.

## 6. Output contract and boundary compliance

Every output uses the envelope from `spec/detector_output_schema.yaml`:
`schema_version`, `concept_id`, `state`, `action_label`, `evidence`,
`confidence`, `notes`, `guardrails`.

- `state` is always one of the contract's `states_emitted`.
- `action_label` is always one of the contract's `allowed_action_labels`, or —
  for a state-only contract — one of its `states_emitted`.
- Guardrail booleans are always present and always `true`. The runtime emits
  the union of the schema's required guardrails
  (`no_trade_permission`, `no_execution_fields`,
  `no_broker_order_account_fields`, `catalog_state_action_checked`) and the
  mission's required guardrails
  (`non_executional`, `no_order_instructions`, `no_position_sizing`,
  `no_broker_or_account_fields`).
- Forbidden execution fields are detected recursively at every nesting depth
  and would raise `OutputError` before an output is returned. No output
  contains any of the 16 forbidden fields.

## 8. Concepts requiring GPT-5.5 / human review

1. **Five state-only contracts** (`ch02_acceptance_vs_rejection`,
   `ch02_structural_reference_levels`, `ch03_initial_balance`,
   `ch03_value_area_vah_val_poc`, `ch03_vwap_relationship`) declare an empty
   `allowed_action_labels` while `spec/detector_output_schema.yaml` mandates an
   `action_label`. The runtime mirrors the state; the validator patch
   formalizes state-only handling. Recommend deciding whether these specs
   should declare action labels or the schema should recognize state-only
   detectors.

2. **Two CALIBRATED contracts with no canonical refusal state**
   (`ch06_stop_out_cascades_and_liquidation`, `ch08_volatility_crush_and_reset`)
   declare no `INSUFFICIENT_EVIDENCE` / `REFUSE_TO_CLASSIFY` /
   `REVIEW_REQUIRED` state. The runtime uses `DEGRADED_CONFIDENCE` as the
   safest available label. Recommend adding an explicit refusal state to those
   specs.

3. **Two COMPUTABLE contracts carrying calibration parameters**
   (`ch03_value_migration_and_overlap`, `ch03_single_prints`) are catalog-class
   `COMPUTABLE` yet declare `calibration_required` parameters. The runtime
   implements their threshold-free structural core only. Recommend confirming
   that the calibration-dependent refinements are correctly out of scope for a
   COMPUTABLE runtime, or reclassifying those parameters.
